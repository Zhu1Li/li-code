# 商汤面试复盘与 Agent 场景训练文档设计

## 目标

基于《商汤一面_原文》转写、LiCode 当前仓库实现和用户提供的岗位 JD，生成一套可用于理解、口头复习和场景设计训练的面试准备材料。

材料必须解决三个问题：

1. 还原本次面试中有技术价值的主问题与追问，并给出准确、可口述的参考回答。
2. 将完整答案压缩成面试前可以快速复习的版本，避免现场回答发散。
3. 围绕小浣熊的 Coding Agent 与办公 Agent 产品方向，训练 Understand–Plan–Execute、多 Agent 并发、长任务状态、企业级记忆、工具容错、结构化 Prompt 和自动化评测能力。

## 文档一：完整复盘问答

### 覆盖范围

按真实面试顺序整理约 30～40 个主问题与重要追问：

1. 自我介绍与项目定位
2. LiCode ReAct/Agent Loop
3. OpenAI 与 Anthropic 流式协议
4. 工具延迟加载与 Prompt Cache
5. 两层上下文管理与 RecoveryState
6. 五类长期记忆、权限和文件存储
7. 多租户记忆数据库建模
8. BGE-M3、dense、sparse、BM25
9. RRF 与 cross-encoder reranker
10. 办公文档 Agent
11. Planner 多轮信息流与 Structured Output
12. System Prompt 与工具设计
13. AI 编程工具、岗位沟通与反问

### 单题结构

每道主问题使用以下结构：

- 问题
- 面试官在考什么
- 推荐回答
- 可能的继续追问
- 追问参考回答
- 本次回答的问题
- 回答时要避免
- JD 延伸追问
- LiCode 实现依据（适用时）

推荐回答应适合口头表达，先给结论，再给数据流、关键不变量和边界情况。避免写成只能阅读、无法在面试中复述的论文式答案。

## 文档三：小浣熊方向 Agent 场景设计训练手册

### 场景分布

- Coding Agent：约 45%
- 办公 Agent：约 35%
- 企业级记忆、工具容错和 Prompt 工程：约 20%

### 十道完整示范题

1. 代码仓库维护 Coding Agent
2. 多 Agent 并行开发系统
3. 跨几十轮的长任务 Coding Agent
4. Coding Agent 工具熔断与容错
5. 操作 Word、PDF、Excel 的办公 Agent
6. 办公多任务并行 Agent
7. 办公文件理解与编辑的 UPE 闭环
8. 企业级多租户 Agent 记忆服务
9. 工具结果到下游模型的稳定信息协议
10. Prompt 自动化评估与回归系统

### 完整示范题结构

- 题目与约束
- 面试官在考什么
- 需求澄清
- 核心设计判断
- 单 Agent、Workflow 或 Multi-Agent 的选择
- Understand–Plan–Execute 信息流
- 状态与记忆设计
- 工具清单
- 关键工具 JSON Schema
- System Prompt
- 两轮或三轮消息示例
- 异常、并发与容错路径
- 权限与安全
- 可观测性与评测指标
- 2～3 分钟口述版答案
- 可能追问及参考回答
- 容易被攻击的设计点

System Prompt 和 Schema 应保持最小、闭合、可运行风格。示例消息必须明确标注 system、user、assistant、tool 的角色，不能把其他模型的自然语言输出伪装成 Planner 自己的历史。

### 十道自主训练题

1. Java 8 到 Java 21 的代码迁移 Agent
2. Pull Request Review Agent
3. CI 故障诊断与修复 Agent
4. 百万行代码库问答与架构理解 Agent
5. 依赖升级 Agent
6. 会议材料生成 Agent
7. 合同对比与修订 Agent
8. 批量 Excel 报表处理 Agent
9. Word/Excel 模板填充 Agent
10. 跨会话办公任务 Agent

每道训练题包含场景约束、必答问题、评分标准、典型陷阱、设计提示和两个追加反例，但不直接给出与示范题同等篇幅的完整答案。

### 通用答题框架

训练手册提供可复用的六段式框架：

1. Understand：目标、输入、约束、可发现事实、澄清点和成功标准。
2. Plan：任务依赖、并行边界、计划版本和重规划条件。
3. Execute：最小工具集、工具结果、审批、验证和失败处理。
4. State and Memory：短期状态、长期记忆、共享状态、压缩和恢复。
5. Reliability：超时、重试、熔断、幂等、冲突和人工接管。
6. Prompt and Evaluation：模块化 Prompt、输出契约、回归样本和量化指标。

## 写作原则

- 使用中文，保留必要英文术语并在首次出现时解释。
- 结论优先，段落适合口述。
- 不用“乱七八糟”“好像”“应该是”等不确定表达作为答案主体。
- 重要设计必须包含失败路径，不能只描述理想流程。
- 先回答题目核心，再讨论缓存、Redis、分库分表等工程扩展。
- 对存在多种合理方案的问题，说明选择依据和替代方案。
- 速背版不引入完整版没有解释的新结论。

## 验收标准

1. 原面试所有重要技术问题都有对应条目，没有按每一句口语机械拆题。
2. LiCode 参考回答与当前代码的数据流一致，并链接关键文件。
3. 完整版与速背版不存在术语、数字或架构矛盾。
4. 十道示范题均包含 UPE、工具、状态、异常和评测，不只给理想流程图。
5. Coding 与办公场景占完整示范题的主要篇幅。
6. 办公 Agent 示例包含 Word、PDF、Excel、沙盒隔离和澄清工具。
7. 多 Agent 示例明确说明并行边界、工作区隔离和冲突处理。
8. 记忆服务示例明确实体粒度、租户过滤、索引、更新语义和延迟指标。
9. 工具协议示例区分人类可读文本与机器可解析字段。
10. Prompt 评测示例同时包含确定性断言和模型评审，能够支持多模型回归。
11. 不含 `TBD`、`TODO`、空章节或未解释的占位符。

## 非目标

- 不修改 LiCode 产品代码。
- 不把文档写成通用 Agent 教科书。
- 不覆盖与 Coding、办公、记忆、工具稳定性和 Prompt 工程无关的泛行业 Agent 场景。
- 不承诺某个架构是所有规模和模型下的唯一最优解。
